This map is meant to be executable.
An editor or agent should be able to use it to make consistent decisions without relying on chat history.

## 4. Keep but Narrow Usage

These terms are not banned, but they need tighter rules so they stop diluting the manuscript.

### 4.1 `Khalorēē`

`Khalorēē` is canonical, but it is currently over-exposed in the compiled corpus.

Current hotspots:

- `Book_2_The_Myocardial_Chorus.md`: 325
- `Book_1_Anamnesis_Engine.md`: 95
- `Book_3_The_Ripening.md`: 28
- omnibus: 454

Rules:

- Keep it when deep reserve, inherited architecture, or structural coherence is actually the point.
- If three nearby uses do not each add a distinct layer of consequence, compress or vary them.
- Prefer specific action, sensation, vessel behavior, or consequence over repeated noun invocation.
- Avoid using `Khalorēē` as a decorative substitute for every kind of force, feeling, or system motion.

### 4.2 `healing`

`healing` is not forbidden, but it is demoted as a governing frame.

Current hotspots:

- omnibus: 49
- Book 3: 19
- Book 1: 17
- Book 2: 13

Rules:

- Keep it for literal or diegetically appropriate repair.
- Keep it in dialogue if that is genuinely how a character would name the process.
- Do not let it serve as the trilogy’s interpretive frame.
- In narration, prefer more exact alternatives when the actual movement is integration, stabilization, revision, or metabolizing.

### 4.3 `WitnessOS`

`WitnessOS` remains valid only as precursor or historical comparison language.

Rules:

- Use only when explicitly contrasting older architecture with active `NOESIS`.
- Do not let `WitnessOS` behave like the live public-facing architecture.
- If a sentence can say `NOESIS` without losing historical precision, prefer `NOESIS`.

### 4.4 Runtime terms: `frequency`, `signal`, `resonance`, `register`

These remain valid, but they must stay tied to measurable or embodied conditions.

Rules:

- Use them in Euclidean-runtime conditions, instrumentation, embodied perception, or collective harmonics.
- Do not let them float upward into generic spiritual wallpaper.
- Prefer `register` when the term marks sustained tonal or structural state rather than raw oscillation.

### 4.5 `journey`

`journey` is demoted but not fully banned.

Rules:

- Allow it in dialogue or limited narration when it is genuinely human speech.
- Do not let it anchor backmatter, glossary, preface, or core interpretive language.
- Replace it when it is just a diluted stand-in for threshold, sequence, arc, or consequence.

## 8. File-Specific Priority Rules

### Frontmatter

- avoid soft, guiding, onboarding phrasing
- avoid ecosystem references unless they behave as conceptual recognition
- prefer threshold, rigor, architecture, and pressure

### Preface

- cut legacy meta-commentary that dissolves authorship
- preserve threshold energy only if it sharpens rather than blurs the thesis

### Backmatter

- remove obsolete brand shells first
- remove overt promotional phrasing
- allow only subtle outward conceptual adjacency

### Glossary

- every entry must match current doctrine
- if an entry mainly preserves a transitional frame, rewrite or cut it
- `WitnessOS` only survives as precursor language

### Book 1 and Book 2

- highest priority: remove exposed scaffolding and reduce over-explained system language
- convert explicit explanatory overlay into dramatic implication wherever possible

### Book 3

- preserve tonal strength
- remove residual artifact language, stale soft-spiritual phrasing, and leftover instructional blocks

## 9. Decision Heuristics

When unsure what to do with a term, ask:

1. Does the term increase structural precision?
2. Does it change consequence in the scene?
3. Does it belong to the active Noesis architecture or to an earlier shell?
4. Is it acting as narrative reality or as explanatory overlay?
5. Would a reader unfamiliar with the ecosystem still experience a coherent novel if it stays?

Decision rule:

- if it increases precision and consequence, keep it
- if it is current but over-exposed, narrow it
- if it gestures at the right thing in weak language, reframe it
- if it belongs to a deprecated shell or exposed editorial scaffold, remove it
